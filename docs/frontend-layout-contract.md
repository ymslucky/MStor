# 前端布局与层叠契约

> 目的：终止"每次改动都可能把布局弄坏"的循环。所有页面/组件必须遵守本文件的区域划分、滚动所有权与层叠顺序。

## 1. 区域划分（AppShell 定义，页面只填内容）

```
┌───────────────────────────────────────────────┐
│ header（TopBar，sticky，z-sticky）             │ 56px
├────────────┬──────────────────────────────────┤
│ nav        │ main                             │ 剩余高度
│ (z-nav)    │  └─ 页面根节点（只负责内容与自身滚动）│
│            │                                  │
├────────────┴──────────────────────────────────┤
│ status（StatusBar，content 层，不滚动）         │ ~28px
└───────────────────────────────────────────────┘
```

- 桌面（md+）：内容列固定 `md:h-dvh`，`main` 是 flex 列且**自己不滚动**。
- 移动：不锁视口高度，整页滚动。

## 2. 滚动所有权（每个页面只能有一个滚动容器）

| 页面 | 滚动容器 | 约定 |
|---|---|---|
| 文件页 | 列表元素自身（`VirtualizedList` 的 `overflow-y-auto`） | 页面不滚，列表填满 `main` 剩余高度；网格视图同理 |
| 回收站 / 分享 / 设置 / 库视图 | 页面（body） | 页面根节点加 `md:pb-4` 补底部留白 |

**规则**：不允许"外层裁剪 + 内层无确定高度"。要么把高度链条显式传下去（每层 `min-h-0 flex-1`），要么整页滚动，二者不可混用。历史上两次事故（480px 假上限、`h-dvh + overflow-hidden` 卡死）都源于违反此条。

## 3. 层叠层级（唯一出处：`index.css` 的 `--z-*`）

| 令牌 | 值 | 用途 |
|---|---|---|
| `z-content` | 10 | 与背景光晕分层的内容（页面根、错误页卡片） |
| `z-sticky` | 20 | 顶栏、表头等 sticky 元素 |
| `z-nav` | 30 | 侧栏 |
| `z-overlay` | 40 | 批量条、上传浮层、拖拽覆盖层、下拉刷新、弹窗遮罩 |
| `z-modal` | 50 | 弹窗/抽屉面板、批量进度 |
| `z-menu` | 60 | 右键菜单、下拉菜单 |
| `z-toast` | 70 | 全局提示 |

**禁止**再写裸 `z-10/20/30/40/50/[n]`；新增浮层先判断它属于哪一层。当前全站裸 z-index 计数为 **0**（可用 `grep -rn 'z-\[' client/src` 自查）。

## 4. 一个状态只渲染一个界面

不要用 CSS 隐藏（`hidden lg:block`）去"关掉"一个会走 Portal 的组件（Dialog/Toast/菜单都会挂到 body，CSS 隐藏无效）。
正确做法：用 `useMediaQuery` 在渲染层二选一（详见 `pages/Browser.tsx` 的 detail 分支）。

## 5. 新增页面检查清单

- [ ] 页面根节点是否需要 `md:pb-4`（整页滚动）或 `md:flex-1 md:min-h-0`（区域滚动）
- [ ] 是否引入了新的滚动容器？如有，确认它是该页面**唯一**的滚动者
- [ ] 所有浮层是否使用 `z-overlay/z-modal/z-menu/z-toast`
- [ ] 是否用 CSS 隐藏处理了会走 Portal 的组件
- [ ] 是否在 `/design` 页登记了新增原语
